중복 후보 검토

이름은 후보를 찾는 근거일 뿐 고유 식별정보가 아닙니다. 후보마다 근거와 신뢰도를 보고 병합 승인, 별개 인물, 추가 검토를 기록합니다. 병합 승인은 여기서 인물을 삭제하지 않습니다.

인증 대기

검토 대기열

후보 새로 계산은 현재 정규화된 이름·활동 기록을 다시 분석합니다. 별개 인물 판정은 근거 식별값이 달라지면 추가 검토로 다시 열립니다.

관리자 인증 후 후보 대기열을 불러옵니다.

현재 병합 실행 경계

MERGE(병합 승인) 판정과 실제 병합은 분리됩니다. 실제 인물 데이터 통합은 서버가 현재 semantic-key v2 reconciliation, 전체 duplicate revalidation frontier, durable requirement, live evidence와 참조 표면을 모두 다시 검증해 merge_execution_state.allowed=true일 때만 제공됩니다. 실행 시 유지할 Person UUID와 관계 정리 방식을 명시한 하나의 PostgreSQL SERIALIZABLE transaction으로 처리하고, 병합 후 후보 frontier를 같은 transaction에서 다시 계산합니다.

시스템 상태 · 읽기 전용

시스템 현황

현재 런타임이 직접 확인할 수 있는 배포 식별자, 설정 존재 여부, 데이터베이스 구조·행 수, 원본 등록·P10 준비 상태와 중복 처리 이력을 표시합니다. 비밀번호·토큰·DB URL 같은 민감한 설정값은 표시하지 않습니다.

인증 대기

관리자 인증 후 시스템 현황을 불러옵니다.

GitHub Actions 결과는 런타임 내부 값이 아니므로 이 API가 임의로 정상 판정을 만들지 않습니다.

객체 조회 · 읽기 전용

UUID 기반 객체 조회

인물·활동·정치체·역할·기간 기준·관계 유형·출처의 기준 UUID를 직접 조회합니다. 지원되는 객체 유형은 서버에서 확인합니다.

인증 대기 
관리자 인증 후 UUID 기반 객체 조회를 사용할 수 있습니다.

객체 조회 화면에는 출처 UUID·키·해시·크기와 출처 위치 정보 중 관리자에게 공개 가능한 항목만 표시합니다. 감사 원장·환경변수·인증 정보는 제공하지 않습니다.

식별정보 등록

신규 식별정보 등록

새 인물·정치체·역할의 식별정보를 먼저 등록합니다. 인물·정치체의 영문 기준명과 한국어 대표 이름은 하나의 일관된 트랜잭션에서 함께 생성합니다.

인물

생존 상태 검토

ATLAS Person DB는 현재 생존 인물을 등록하지 않습니다. 활동 종료연도·진행 중 여부·대표 활동연도는 생존 판정에 사용하지 않습니다.

정치체

역할

역할 정보는 정확한 조회를 위해 코드·영문 표기·한국어 이름의 중복을 자동 허용하지 않습니다.

식별정보 등록 준비 완료

활동 관계 JSON 입력

먼저 위에서 필요한 식별정보를 만든 뒤 활동 관계를 저장합니다. 동일 활동 판정은 인물 + 정치체 + 관계 + 역할(없음 가능) + 기간 기준 + 전체 시작·종료 시점를 사용합니다. 역사 연도 0은 허용하지 않습니다.

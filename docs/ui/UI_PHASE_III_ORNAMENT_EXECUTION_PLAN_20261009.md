## 0. 개정 이유 및 현재 구현상태

기존 v1은 고지도·천문기구·장식 필사본의 존재감을 강화하고, 장식 후보 42개 중 우선순위 19개를 화면별로 시안화하도록 제안했다. 그 결과 VIS3-04/05의 첫 Production은 상단 대시보드 제목을 겹치는 카르투슈, 데이터 대시보드 제목을 덮는 프레임, 대형 나침반, 핵심 통계 명패·마름모 구분선, 사이드바 모서리·버전 명패가 동시에 나타났다. 실제 사용자 제공 화면에서는 역사성보다 장식의 반복과 텍스트 충돌이 강하게 느껴졌다.

PR #2340의 후속 수정은 제목을 가리는 문양을 제거하고 브랜드 34px 로제트, 대시보드 우상단 54px 저채도 모서리 장식, 핵심 통계의 얇은 구분선만 남겼다. 사용자가 올린 후속 실제 화면은 균형과 가독성은 크게 회복했지만, 역사 아틀라스만의 편집적 개성은 충분하지 않다는 평가를 받았다. 사용자가 직접 제공한 캡처는 중요한 디자인 증거이지만, 그 자체를 자동화된 exact-SHA Chrome 인증으로 표시하지 않는다.

## 1. 수정된 목표

ATLAS는 역사 데이터에 황동 장식을 많이 붙인 관리 화면이 아니라, 고급 역사 도록의 편집 품질과 현대 데이터 도구의 탐색성을 함께 지닌 제품이어야 한다.

우선순위:
1. 제목/숫자/시대/지역/자료의 정보 위계와 시각적 판독성.
2. 균형 있는 여백, 섬세한 서체, 소재와 대비, 안정적인 정렬.
3. 의미 있는 진입부에 배치된 소수의 역사적 세공.
4. 화면 사이의 정체성 통일과 문화권별 실제 근거.
5. 도메인 기능, 데이터 정확성, 속도, 모바일 접근성의 보존.

강한 장식을 추가했다는 이유만으로 개선으로 판정하지 않는다. 반대로 장식을 모두 없애 일반적인 회계/관리 대시보드가 된 것도 성공으로 판정하지 않는다.

예산은 화면 전체에서 강한 시그니처 최대 1개와 조용한 보조 최대 1개를 기본으로 하며, **0개도 합격 가능**하다. 이것은 전 화면에 새 SVG를 최소 하나 이상 억지로 넣으라는 규칙이 아니다. 숫자/데이터 카드마다 재사용하는 장식은 0개.

고색 황동은 분류용 governance Gold #D4AF37과 구분한다. 종교/문화 문양, 공식 국장, 신분·계보·연대는 역사적 근거 없이 만들어내지 않는다.

## 4. 최우선 신규 작업단위 VIS3-05R — 실제 화면 기반 교정 및 선택

기존 VIS3-06 착수 전에 이 단위를 진행한다. 단계별 완료 경계를 나누며, 시안 승인 전에는 Production CSS를 직접 변경하지 않는다.

### VIS3-05R-A — 실화면 기준 고정 (읽기 전용)

1. 사용자가 제공한 과장식 화면과 과잉 제거 후 화면을 별도 피드백 증거로 인덱싱한다.
2. 현재 배포 source SHA와 실제 Chrome 화면의 대응을 확인한다. 390, 768, 1440, 1600 CSS px를 캡처한다. 1885px 사용자 캡처의 수치와 현재 운영 KPI 값은 시안에서 임의 교체하지 않는다.
3. Dashboard 6개 KPI 값/클릭 가능·불가 상태, 새로고침, 섹션 위치, 사이드바 메뉴, 연결 확인 중 상태를 동일한 실제 데이터로 고정한다.
4. 현재 34px 로제트, 54px 저채도 코너와 1px 구분선 및 V11 자재/폰트 설정을 기준선으로 보관한다. 이미 해소된 대형 겹침 문제를 재현하지 않는다.

**A 완료:** 비교할 실제 화면·SHA·데이터 상태·텍스트 길이·레이아웃을 명시한 재현 자료 확보. 코드 편집 0.

### VIS3-05R-B — 시안 4종 비교 (비배포)

| 시안 | 내용 | 비교 목적 |
| --- | --- | --- |
| A / Current | 현재 배포 UI 그대로 | 추가 장식이 정말 필요한지 판단하는 제어군 |
| B / Edge | 메인 권두 모서리 유지 + 부분 1px 이중 판각선/끝처리 | 제목 가림 없이 권두의 역사 도록 품격 강화 |
| C / Ledger | 현재 권두 유지 + 핵심 통계 110~150×24~32px의 단순 명패 및 최대 5~7px 끝장식 | 작은 장부 표제만으로 인상 개선 가능한지 판단 |
| D / Combined | B+C에서 필요하다고 선택된 요소만, 각 장식의 대비를 낮춰 한 번 재조율 | 동시 적용이 개별안보다 시각적으로 나은지 검증 |

B/C/D에는 기존 다층 SVG를 축소 복제하지 말고 불필요한 곡선·내부 선·중앙 큰 마름모를 제거한 신규 경량형을 사용한다. 기존 실화면과 같은 DOM 데이터/같은 viewport를 비교한다. 장식이 텍스트 또는 버튼/통계 위로 들어오면 점수와 관계없이 폐기한다.

**B 완료:** 1440 및 390 화면별 A/B/C/D 비교 자료, 예상 화면 점유/겹침 체크, 장식별 채택·폐기 후보표. Production 변경 0.

### VIS3-05R-C — 사용자 시안 결정

- 사용자에게 A 유지, B만, C만, D 제한 혼합 중 선택을 받는다.
- 채택 불가로 판단된 장식은 같은 PR이나 다음 단계에서 슬그머니 부활시키지 않는다.
- 승인 전 canonical Visual Guidelines의 실제 강도 표를 고치지 않는다.

**C 완료:** 시안별 승인/거절 이유와 최종 선택 항목 1~2개 기록.

### VIS3-05R-D — 선택된 조형만 소형 구현

- 승인된 부위만 기존 atlas-ui-phase3-ornaments.css 내에서 수정한다. 불필요한 CSS override 누적 금지. 필요한 경우 경량 SVG 1종만 추가한다.
- 렌더러의 업무 KPI 호출, 6개 수치/드릴다운, 새로고침 버튼, 탐색, 상태 표시, 데이터 원본은 변경하지 않는다.
- 코드 회귀 테스트는 **장식이 존재하는가**보다 **겹치지 않는가·기능에 닿지 않는가·불필요한 SVG를 쓰지 않는가**를 검사한다.
- 수정의 목적이 시각적 표현이라면 DB/API/Runtime을 건드리지 않는다.

**D 완료:** 제한된 코드 변경, 목적에 맞는 테스트 성공, 원본 기능 보존. 이 상태는 시각 최종 승인이 아니다.

### VIS3-05R-E — 브라우저 승인·종결

- 동일 배포 SHA에서 같은 DOM/데이터의 장식 ON/OFF 화면과 승인된 A/B/C/D의 기대 상태를 비교한다.
- 390/768/1440/1600, 125%·150% 실효 확대, 키보드 탐색/포커스, 실제 SVG 200 응답, 인물/시공간 기능 간섭을 확인한다.
- 실화면 텍스트 겹침 0, 추가 스크롤 0, 버튼 hit box 가림 0, 6 KPI 값·동작 불변을 증거로 남긴다.
- 사용자 육안 최종 승인을 별도 기록한다. 마음에 들지 않으면 현재 A로 되돌리고 다른 화면 작업을 강행하지 않는다.

**E 완료:** 정확한 Production SHA, 실화면 스크린샷, 테스트, 사용자 승인 모두 확보.

## 5. 별도 정밀 작업 VIS3-05T — 가독성·사이드바 품질

사용자 제공 현재 화면의 잔여 문제를 장식 수로 해결하지 않는다.

- 사이드바의 '시공간 인물도' 두 줄과 옆 상태 텍스트 사이의 충돌/읽기 순서, 접기 버튼의 경계 정렬 검토.
- KPI 하단 설명, 상태 텍스트, 우측 메타데이터의 너무 어두운 명도·작은 폰트·긴 내용 잘림 검토.
- 제목, 보조 설명, KPI 수치의 한글/영문 혼합 타이포, 실제 데이터의 표형 읽기 순서 재정렬.
- '연결 확인 중' 표시가 이미 KPI가 표시된 상태에서도 오래 유지되는 경우는 시각 장식 이슈와 분리하여 실제 네트워크/상태 갱신 로직을 조사한다. 데이터가 성공적으로 갱신됐다고 가정하지 않는다.
- 시공간표 등 다른 도메인의 사이드바·메뉴 동작이 공동 소유권을 사용하므로 영향 범위를 검증한다.

VIS3-05T는 정보 위계/접근성 작업으로 분류한다. VIS3-05R과 CSS 소유권이 겹치는 변경은 별도 검증·순서 관리를 사용한다.

## 8. Canonical 가이드라인 충돌 처리

ATLAS_UI_VISUAL_GUIDELINES.md v2.0은 현재 §14(금속 강조), §17(연대와 장식), §22(장식 예산), §24(디자인 결정), §27(화면 역할), §28(변경불가 계약)에서 장식의 가시성을 강하게 요구한다. 이 문서의 새 사용자 피드백은 §22의 높은 카르투슈 강도와 화면당 1개 대표 + 1~2개 보조의 자동적 해석에 제약을 추가한다.

**현재 계획 문서에서는 수정 방향을 제안하지만 canonical 문서는 별도 승인 없이 수정하지 않는다.** VIS3-05R-C에서 디자인 안이 선택되면 독립적인 가이드라인 정합화 PR로 다음을 반영한다:

1. '장식이 분명해야 한다'에서 '콘텐츠를 해치지 않는 범위에서 역사적 인상이 남아야 한다'로 우선순위 정렬.
2. 한 화면에 0~1개 대표+0~1개 보조까지 허용하되, 0개도 문맥상 적합하면 가능.
3. 실명/실제 연도/소스/툴팁 위로 장식 배치 금지, 반복 데이터행에는 없음.
4. 시공간·인물 상세·정치체의 서로 다른 역할과 시대·지역 근거 유지.
5. 임의의 공식 문장과 허구 국장, 데이터처럼 보이는 장식형 눈금과 표기는 계속 금지.

변경하지 않는 canonical 계약: Spacetime 500~1500%, X/Y unified, compression 0.748, nine macroregions, 140px axis, Person dense register, eight semantic colors, P14 PARKED_BY_USER, VIS2-05 watermark REJECT/OFF.

## 9. 실행·문서화·종결 규칙

- 작업 단위별로 직접 관련 CSS/HTML/JS·GitHub 상태만 확인, 같은 조사를 반복하지 않는다.
- 시안 제작과 데이터 로직의 수정은 분리하고, 동일 자원 CSS 파일은 최신 base 확인 후 충돌 범위만 갱신한다.
- 사용자 시안 선택 전에는 Phase III 화면 구현을 시작하지 않는다. 기획안의 승인과 실제 CSS 배포 승인을 구별한다.
- 작업 단위 하나를 실제 완료할 때마다 실행 코드/테스트/스크린샷/남은 승인 사항/정확한 재개 지점을 보고한다.
- 주요 화면의 최종 장식 승인 전에는 VIS3-16/17 최종 완료를 선언하지 않는다.
- 다른 도메인에서도 **과도한 장식을 즉시 제거하는 긴급 수정**이 필요하다면, 과한 구현을 확장하지 않고 먼저 실화면 안정성을 회복한다.

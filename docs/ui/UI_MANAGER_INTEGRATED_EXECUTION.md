# ATLAS UI 작업 매니저 — 통합 계획·실개발·수용 관리 계약

> ACTIVE / 2026-11-19 KST. 총괄: 기존 'ATLAS 프로젝트 총괄' 예약(8회/일, 일정 변경 없음). UI 책임 원장: Issue #1896. 프로젝트 통합 원장: Issue #2627.
>
> 목표는 과거 UI 기획을 다시 쓰거나 개별 CSS PR을 쌓는 것이 아니라, **역사 아틀라스의 모든 승인된 UI 목표를 한 눈에 관리하고 실제 Production에서 남은 미완료를 줄이는 것**이다. 이 문서는 UI 매니저의 라우팅·감독 규칙이다. 승인된 세부 디자인이나 기능·데이터 권한을 새로 부여하지 않으며 WORK_EXECUTION.md, ATLAS_REQUIREMENTS.md, DATA_MODEL.md의 안전·의미 계약을 변경하지 않는다.

## 1. 총괄과 UI 매니저의 책임 구분

- **총괄(오케스트레이터):** 매 실행 시 UI 매니저의 종합 상태를 확인하고 UI 작업이 전역 P0, Canonical Writer, 다른 PR과 충돌하지 않도록 우선순위·실행 환경·검증 경계를 조정한다. UI를 다른 CORE 업무 종료까지 대기시키지 않는다. 승인·비용·운영 변경을 우회하지 않으며, UI 변경 파일의 원소유자를 확인한다.
- **UI 매니저(상시 책임 역할, 별도 유료 인력·예약이 아님):** 아래 *전체* 설계 계보를 관리한다. 최신 결정·이미 반영된 결과·검증 대기·승인 대기·폐기된 제안을 구별한다. 분야별 구현자에게 정확한 **화면·소스·회귀조건·수용조건**을 지정하거나 도구가 지원하면 직접 실행한다. 여러 작업의 결과가 최종 제품의 통일감·조작·의미·정보 범위를 충족하는지 교차 검사한다.
- **실행자:** 실제 기존 소스에 변경을 통합하고 집중 테스트, exact-head CI, Review, merge, Production 확인, 브라우저 수용증거를 전달한다. 별도 샘플·시안·문서·CI만으로 UI 기능 완료를 주장하지 않는다.
- 총괄이 UI 매니저를 별도 에이전트로 실제 실행하지 않았다면 '하위 AI 배치/작업 완료'라고 보고하지 않는다. 하나의 Work 실행이 매니저와 실행자 역할을 연속 수행할 수 있다. 새로운 스케줄·유료 자원은 만들지 않는다.

## 4. 매 실행 체크 계약 — 총괄이 UI 매니저에게 요구할 것

1. **전역 확인:** GitHub main, UI 관련 열린 PR/현재 branch, #1896 최신 원장, 이 인덱스 및 UI-01~07의 현행 상태를 조회한다. 마지막 회차의 다음 지시가 이미 완료되었으면 중복 없이 다음 실제 미완료로 이동한다.
2. **전체 범위 누락 점검:** 시각 고급화(Premium/Phase III), 화면별 구조, 시공간, 역사 의미·출처·불확실성, Admin, 한국어, 모바일/접근성, 로딩·오류·상호작용을 **한 번에 전체 범주로** 점검한다. 매번 수십 원문 재열람 대신 각 범주가 이 원장에 살아 있는지 확인한다.
3. **실행 선택:** 유효 승인 여부 → 사용자 실제 효과/근본 결함 → 다수 화면에 걸친 공통 원인 → 회귀/충돌/비용을 비교한다. 이미 구현된 항목·보류/거절 제안은 제외. 해결할 가장 큰 실제 문제 1개를 정확한 파일·원본 상태·테스트·종결 게이트와 연결한다. 코드 실행 가능 시 문서·검토로만 회차를 끝내지 않는다.
4. **구현·교차 검증:** 기존 코드 직접 변경, 집중 회귀 테스트, exact-head CI, 리뷰/동시 파일 변경, merge, Vercel 실제 자산/버전, 해당 화면 PC·모바일 실제 브라우저 동작·전후 비교로 검증. 화면이 데이터 내용을 누락·왜곡하거나 8분야 의미색/시공간 좌표를 바꾸지 않았는지 확인. 제한된 분리 가능한 실작업 단위를 완료하고 증거를 남긴다.
5. **상태와 보고:** UI-01~07 및 향후 추가된 트랙 각각 DONE/PARTIAL/MISSING/APPROVAL_HOLD/PARKED로 현재 상태와 결함·증거를 유지한다. 작업 1건마다 CODE CHANGED, CI PASS, MERGED, PRODUCTION LIVE, VISUALLY ACCEPTED, USER APPROVED를 서로 구분한다. 총괄에게 이번 실제 결과·막힌 승인·영향 범위·다음 정확한 실행 파일/PR을 보고한다.
6. **총괄의 감독:** UI 매니저의 보고에 *전 트랙 누락은 없는가? 계획 간 충돌은 정리했는가? 새 PR만 생기고 실제 운영 화면이 그대로인가? Source/좌표/의미색/권한 회귀는 없는가? 다음 행동이 실개발인가?*를 확인한다. 문제 있으면 매니저에 재선정/교정을 지시한다. 한 회차 UI 변경이 어려우면 근거를 기록하고 다른 독립 UI 작업으로 전환한다. 전체 UI를 '계획 완료'로 선언하지 않는다.

**현행 v1.1 확장 의무:** 최신 실행 계획에는 UI-01A/B(명부와 다중 Activity), UI-02A, UI-03A/B(연도·권역·LOD), UI-04/05 외에 **UI-06A 동시대 전체 결과 탐색 / UI-06B 인물↔시공간 탐험 상태 복원 / UI-07 두 인물 활동·정치체 비교**가 포함된다. UI-05 '1차 수용'만으로 전체 역사탐험을 완료라고 주장하지 않는다. 앞으로 승인된 추가 기획은 이 인덱스의 트랙·상태에 합치고 7개 번호를 인위적 상한으로 삼지 않는다.
